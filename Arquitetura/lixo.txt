# Checklist para entrevistas — Estruturas de Dados

---

## 1. Explica como escolher uma estrutura de dados?

> Um desenvolvedor Senior não deve decorar estruturas de dados. Deve saber escolher a estrutura adequada para cada cenário.

Antes de escolher, eu avalio:

| Critério       | Pergunta                        |
| -------------- | ------------------------------- |
| Leitura        | Quantas consultas serão feitas? |
| Escrita        | Quantas inserções/atualizações? |
| Busca          | Preciso buscar por chave?       |
| Ordenação      | Preciso manter ordenado?        |
| Memória        | Qual o volume de dados?         |
| Concorrência   | Haverá múltiplas threads?       |
| Latência       | Qual o SLA/P99 esperado?        |
| Escalabilidade | Vai crescer para milhões?       |

Exemplo:

Se preciso encontrar um usuário pelo ID:

```java
Map<Long, User>
```

Complexidade:

```text
O(1)
```

Não faz sentido usar:

```java
List<User>
```

pois a busca seria:

```text
O(n)
```

---

## 2. Entende complexidade computacional (Big O)?

> Estruturas de dados são avaliadas principalmente pela complexidade das operações.

### Complexidades mais importantes

| Complexidade | Nome         |
| ------------ | ------------ |
| O(1)         | Constante    |
| O(log n)     | Logarítmica  |
| O(n)         | Linear       |
| O(n log n)   | Quase linear |
| O(n²)        | Quadrática   |

---


### Resposta Senior

> Eu não decoro apenas Big O. Eu relaciono complexidade com volume real. Uma busca O(n) em 10 registros é irrelevante. Em 100 milhões de registros pode inviabilizar o sistema.

---

## 3. Sabe quando usar List, Set e Map?

### Definição

| LIST | SET         |Map|
| ------------ | ------------ | ------------ |
|Mantém ordem         |    Ordem com implementação da interface (treeSet, LinkedHashSet) | Associação Chave -> valor
| Permite duplicados     | Não permite duplicados  |

### Quando Usar
 | LIST | SET         |Map
| ------------ | ------------ |------------ |
|sequência de elementos        |    Ordem com interface (treeSet, LinkedHashSet) | lookup rápido
| Paginação  |UUnicidade  |cache;
| Ordenação  |Remoção de duplicidade  | indexação.

### Exemplo
 | LIST | SET         |Map
| ------------ | ------------ | ------------ |
| ```List <Order>```   |```Set <Permission>```   |```Map <Long, Customer>```

### Busca
 | LIST | Set         |Map
| ------------ | ------------ | ------------ |
| ```for (User user : users)```   |```Set <Permission>```   |```map.get(id)```
| Complexidade O(n)  |``` Complexidade O(1) no HashSer```   |``` Complexidade O(1)```
|| ``` Complexidade O(logn) no TreeSet```

### Resposta Senior

> Se preciso localizar elementos por chave, geralmente uso Map. Se preciso apenas armazenar sequência, uso List. Se preciso garantir unicidade, uso Set.

---

## 4. Entende ArrayList internamente?

### Estrutura

 | Bom | Ruim         |
| ------------ | ------------ |
|     Acesso por indece  O(1)        |  inserção e remoção no meio ou inicio O(n)            |
|   inserções no final    O(1)        |               |



Quando adiciona ou remove no meio ou início todos os elementos precisam ser deslocados.


```java
ArrayList
```

não é ideal para filas, pois a fila sendo FIFO, a complexidade pode chegar a O(n).

---

## 5. Entende HashMap internamente?
---

### Estrutura

HashMap utiliza:

```text
Array + Hash Function
```

---

Fluxo:

```text
hash(key)
↓
bucket
↓
valor
```

---

### Complexidade

Busca:

```text
O(1)
```

média.

---

### Colisão

Duas chaves podem gerar mesmo bucket.

```text
hash(A) = 10
hash(B) = 10
```

---

Java 8+

Quando há muitas colisões:

```text
LinkedList → Red Black Tree
```

---

### Complexidade pior caso

```text
O(log n)
```

---

### Resposta Senior

> O HashMap fornece busca média O(1), mas depende de uma boa distribuição do hash. Muitas colisões degradam desempenho. Desde o Java 8 buckets muito grandes são convertidos para árvores balanceadas.

---

## 6. Entende equals() e hashCode()?

> Pergunta obrigatória para quem usa HashMap e HashSet.

---

### Problema

```java
User user1 = new User(1L);
User user2 = new User(1L);
```

São iguais?

Depende.

---

Sem implementação:

```java
false
```

---

### Contrato

Se:

```java
equals() == true
```

então:

```java
hashCode()
```

deve ser igual.

---

### Problema real

```java
HashSet<User>
```

duplicando usuários.

---

### Resposta Senior

> HashMap depende diretamente de hashCode para localizar buckets e equals para validar igualdade. Um contrato incorreto pode gerar comportamento inconsistente e perda de performance.

---

## 7. Entende árvores?

### Problema

Listas não escalam bem para buscas ordenadas.

---

### Binary Search Tree

```text
        50
       /  \
     25    75
```

---

Busca:

```text
O(log n)
```

em árvore balanceada.

---

### Uso real

Java utiliza árvores em:

```java
TreeMap
TreeSet
```

---

### Quando usar

* range query;
* ranking;
* ordenação contínua.

---

Exemplo:

```java
TreeMap<Instant, Transaction>
```

---

## 8. Entende Heap?

Não Heap da JVM.

Heap como estrutura de dados.

---

### Min Heap

Menor elemento fica na raiz.

```text
      10
     /  \
   20   30
```

---

### Operações

Inserção:

```text
O(log n)
```

Remoção:

```text
O(log n)
```

---

### Uso real

Fila de prioridade.

```java
PriorityQueue
```

---

Exemplo:

```java
PriorityQueue<Job>
```

scheduler de processamento.

---

## 9. Entende filas e pilhas?

### Stack (LIFO)

Último entra.

Primeiro sai.

```text
3
2
1
```

---

Uso:

* recursão;
* parser;
* execução de métodos.

---

### Queue (FIFO)

Primeiro entra.

Primeiro sai.

```text
1
2
3
```

---

Uso:

* Kafka;
* RabbitMQ;
* filas de processamento.

---

### Exemplo real

```java
BlockingQueue
```

---

## 10. Entende estruturas concorrentes?

> Muito comum em entrevistas Java Senior.

---

### Problema

```java
HashMap
```

não é thread-safe.

---

### Solução

```java
ConcurrentHashMap
```

---

Benefícios:

* lock granular;
* alta concorrência.

---

### Exemplo real

Cache local:

```java
ConcurrentHashMap<String, Session>
```

---

### Outras estruturas

```java
ConcurrentLinkedQueue
CopyOnWriteArrayList
BlockingQueue
```

---

## 11. Sabe justificar trade-offs?

Essa é a diferença entre Pleno e Senior.

---

### ArrayList

Vantagens:

* acesso rápido.

Desvantagens:

* inserções no meio custosas.

---

### LinkedList

Vantagens:

* inserção local eficiente.

Desvantagens:

* cache locality ruim;
* busca lenta.

---

### HashMap

Vantagens:

* lookup rápido.

Desvantagens:

* consumo de memória;
* sem ordenação.

---

### TreeMap

Vantagens:

* ordenação.

Desvantagens:

* mais lento.

---

### Resposta Senior

> Não existe estrutura melhor. Existe estrutura mais adequada para determinado padrão de acesso, volume, concorrência e requisitos de ordenação.

## Resposta de nível Senior (resumida)

> Estruturas de dados são uma ferramenta para otimizar acesso, armazenamento e processamento de informações. A escolha correta depende do padrão de acesso, volume de dados, requisitos de ordenação, concorrência e consumo de memória. Em Java, compreender profundamente estruturas como ArrayList, HashMap, ConcurrentHashMap, TreeMap e PriorityQueue é essencial, não apenas para entrevistas, mas para tomar decisões arquiteturais em sistemas distribuídos, caches, bancos de dados e aplicações de alta escala.

---

# O que normalmente diferencia um Senior

Um Pleno geralmente sabe:

* O que é List;
* O que é Set;
* O que é Map;
* Complexidade básica.

Um Senior sabe explicar:

* Como HashMap funciona internamente;
* Colisões e rehash;
* Cache locality;
* Heap vs Tree;
* Estruturas concorrentes;
* Impactos de memória;
* Trade-offs arquiteturais;
* Como estruturas aparecem em Kafka, Redis, bancos de dados e frameworks Java.
