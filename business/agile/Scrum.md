# Português — Seção 4: Scrum

## Resumo enxuto

| Tópico          | Ideia principal                                                                        |
| --------------- | -------------------------------------------------------------------------------------- |
| Scrum           | Framework ágil para entregar valor em ambientes complexos                              |
| Foco            | Trabalhar em ciclos curtos, inspecionar resultados e adaptar o plano                   |
| Ciclo principal | Sprint                                                                                 |
| Base            | Transparência, inspeção e adaptação                                                    |
| Visão de gestão | Organizar prioridades, reduzir riscos, alinhar stakeholders e melhorar previsibilidade |

---

## Pilares do Scrum

| Pilar         | Significado                                                    |
| ------------- | -------------------------------------------------------------- |
| Transparência | O trabalho, os problemas e o progresso precisam estar visíveis |
| Inspeção      | O time verifica frequentemente produto, processo e progresso   |
| Adaptação     | O time ajusta plano, escopo ou processo conforme aprende       |

---

## Papéis no Scrum

| Papel         | Responsabilidade principal                                               |
| ------------- | ------------------------------------------------------------------------ |
| Product Owner | Maximizar valor e priorizar o Product Backlog                            |
| Scrum Master  | Facilitar o Scrum, remover impedimentos e melhorar a efetividade do time |
| Developers    | Criar incrementos utilizáveis do produto                                 |

---

## Artefatos do Scrum

| Artefato           | Para que serve                                        |
| ------------------ | ----------------------------------------------------- |
| Product Backlog    | Lista ordenada de tudo que pode melhorar o produto    |
| Sprint Backlog     | Plano de trabalho da Sprint atual                     |
| Increment          | Entrega utilizável produzida pelo time                |
| Definition of Done | Critério que define quando algo está realmente pronto |

---

## Eventos do Scrum

| Evento               | Objetivo                                                |
| -------------------- | ------------------------------------------------------- |
| Sprint               | Ciclo curto de entrega e aprendizado                    |
| Sprint Planning      | Definir objetivo, escopo e plano da Sprint              |
| Daily Scrum          | Inspecionar progresso diário e ajustar o plano          |
| Sprint Review        | Avaliar o incremento com stakeholders e colher feedback |
| Sprint Retrospective | Melhorar processo, colaboração e qualidade              |

---

## Scrum na gestão de projetos

| Situação                  | Como Scrum ajuda                           |
| ------------------------- | ------------------------------------------ |
| Escopo incerto            | Permite adaptação por Sprint               |
| Muitas prioridades        | Product Backlog organiza e ordena demandas |
| Baixa visibilidade        | Eventos e artefatos aumentam transparência |
| Risco alto                | Entregas incrementais reduzem incerteza    |
| Stakeholders desalinhados | Sprint Review aproxima negócio e time      |
| Processo ineficiente      | Retrospectiva gera melhoria contínua       |

---

## O que memorizar

| Pergunta                        | Resposta curta                                        |
| ------------------------------- | ----------------------------------------------------- |
| Para que serve Scrum?           | Para entregar valor de forma incremental e adaptativa |
| O que é uma Sprint?             | Ciclo curto de trabalho, entrega e aprendizado        |
| Quem prioriza o backlog?        | Product Owner                                         |
| Quem facilita o processo?       | Scrum Master                                          |
| Quem cria o incremento?         | Developers                                            |
| Scrum é metodologia completa?   | Não; é um framework leve                              |
| Principal benefício para gestão | Mais visibilidade, foco, adaptação e previsibilidade  |

# English — Section 4: Scrum

## Short Summary

| Topic           | Main Idea                                                                         |
| --------------- | --------------------------------------------------------------------------------- |
| Scrum           | Agile framework for delivering value in complex environments                      |
| Focus           | Work in short cycles, inspect results, and adapt the plan                         |
| Main cycle      | Sprint                                                                            |
| Foundation      | Transparency, inspection, and adaptation                                          |
| Management view | Organize priorities, reduce risks, align stakeholders, and improve predictability |

---

## Scrum Pillars

| Pillar       | Meaning                                                    |
| ------------ | ---------------------------------------------------------- |
| Transparency | Work, problems, and progress must be visible               |
| Inspection   | The team frequently checks product, process, and progress  |
| Adaptation   | The team adjusts plan, scope, or process based on learning |

---

## Scrum Roles

| Role          | Main Responsibility                                                  |
| ------------- | -------------------------------------------------------------------- |
| Product Owner | Maximize value and prioritize the Product Backlog                    |
| Scrum Master  | Facilitate Scrum, remove impediments, and improve team effectiveness |
| Developers    | Create usable product increments                                     |

---

## Scrum Artifacts

| Artifact           | Purpose                                                 |
| ------------------ | ------------------------------------------------------- |
| Product Backlog    | Ordered list of everything that may improve the product |
| Sprint Backlog     | Work plan for the current Sprint                        |
| Increment          | Usable delivery produced by the team                    |
| Definition of Done | Criteria that define when work is truly complete        |

---

## Scrum Events

| Event                | Objective                                                   |
| -------------------- | ----------------------------------------------------------- |
| Sprint               | Short cycle of delivery and learning                        |
| Sprint Planning      | Define the Sprint goal, scope, and plan                     |
| Daily Scrum          | Inspect daily progress and adapt the plan                   |
| Sprint Review        | Review the increment with stakeholders and collect feedback |
| Sprint Retrospective | Improve process, collaboration, and quality                 |

---

## Scrum in Project Management

| Situation               | How Scrum Helps                               |
| ----------------------- | --------------------------------------------- |
| Uncertain scope         | Allows adaptation by Sprint                   |
| Too many priorities     | Product Backlog organizes and orders demand   |
| Low visibility          | Events and artifacts increase transparency    |
| High risk               | Incremental delivery reduces uncertainty      |
| Misaligned stakeholders | Sprint Review brings business and team closer |
| Inefficient process     | Retrospective drives continuous improvement   |

---

## What to Memorize

| Question                         | Short Answer                                           |
| -------------------------------- | ------------------------------------------------------ |
| What is Scrum used for?          | To deliver value incrementally and adaptively          |
| What is a Sprint?                | A short cycle of work, delivery, and learning          |
| Who prioritizes the backlog?     | Product Owner                                          |
| Who facilitates the process?     | Scrum Master                                           |
| Who creates the increment?       | Developers                                             |
| Is Scrum a complete methodology? | No; it is a lightweight framework                      |
| Main management benefit          | More visibility, focus, adaptation, and predictability |
