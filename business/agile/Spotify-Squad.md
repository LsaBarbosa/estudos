# Português — Seção 9: Modelo Spotify Squads

## Resumo enxuto

| Tópico             | Ideia principal                                                            |
| ------------------ | -------------------------------------------------------------------------- |
| Spotify Squads     | Modelo organizacional para escalar times ágeis com autonomia e alinhamento |
| Foco               | Times pequenos, multidisciplinares e responsáveis por uma missão           |
| Uso em gestão      | Melhorar autonomia, colaboração, ownership e velocidade de decisão         |
| Não é              | Um framework rígido como Scrum ou SAFe                                     |
| Principal objetivo | Equilibrar autonomia dos times com alinhamento organizacional              |

---

## Estrutura principal

| Elemento | Explicação curta                                                       |
| -------- | ---------------------------------------------------------------------- |
| Squad    | Time pequeno e multidisciplinar, parecido com uma equipe ágil          |
| Tribe    | Grupo de Squads que trabalham em uma área relacionada                  |
| Chapter  | Pessoas da mesma especialidade, como design, produto, engenharia ou QA |
| Guild    | Comunidade de interesse para compartilhar conhecimento e boas práticas |

O modelo Spotify é geralmente descrito como uma abordagem orientada a pessoas para escalar agilidade, usando **squads, tribes, chapters e guilds** para combinar autonomia, aprendizado rápido e colaboração em rede. ([Atlassian][2])

---

## Spotify Squads na gestão de projetos

| Situação                                   | Como ajuda                                             |
| ------------------------------------------ | ------------------------------------------------------ |
| Muitos times trabalhando no mesmo produto  | Organiza Squads por missão ou área de produto          |
| Times dependentes de aprovação central     | Dá mais autonomia para decisão local                   |
| Falta de padronização técnica ou funcional | Chapters ajudam a manter alinhamento por especialidade |
| Conhecimento espalhado                     | Guilds compartilham práticas entre áreas               |
| Produto grande e complexo                  | Tribes agrupam Squads relacionados                     |
| Baixa colaboração entre times              | Cria redes de colaboração além da hierarquia formal    |

# English — Section 9: Spotify Squads Model

## Short Summary

| Topic          | Main Idea                                                             |
| -------------- | --------------------------------------------------------------------- |
| Spotify Squads | Organizational model to scale Agile teams with autonomy and alignment |
| Focus          | Small, cross-functional teams responsible for a clear mission         |
| Management use | Improve autonomy, collaboration, ownership, and decision speed        |
| What it is not | A rigid framework like Scrum or SAFe                                  |
| Main goal      | Balance team autonomy with organizational alignment                   |

---

## Main Structure

| Element | Short Explanation                                                           |
| ------- | --------------------------------------------------------------------------- |
| Squad   | Small cross-functional team, similar to an Agile team                       |
| Tribe   | Group of Squads working in a related product area                           |
| Chapter | People with the same specialty, such as design, product, engineering, or QA |
| Guild   | Community of interest for sharing knowledge and best practices              |

---

## Spotify Squads in Project Management

| Situation                                 | How It Helps                                           |
| ----------------------------------------- | ------------------------------------------------------ |
| Many teams working on the same product    | Organizes Squads by mission or product area            |
| Teams dependent on central approval       | Gives more autonomy for local decision-making          |
| Lack of technical or functional standards | Chapters help maintain alignment by specialty          |
| Knowledge spread across teams             | Guilds share practices across areas                    |
| Large and complex product                 | Tribes group related Squads                            |
| Low collaboration between teams           | Creates collaboration networks beyond formal hierarchy |
