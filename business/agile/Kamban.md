# Versão em Português — Seção 5: Kanban

## Resumo enxuto

| Tópico               | Ideia principal                                                              |
| -------------------- | ---------------------------------------------------------------------------- |
| O que é Kanban       | Método visual para gerenciar fluxo de trabalho e melhorar entrega de valor   |
| Foco                 | Visualizar trabalho, limitar trabalho em progresso e melhorar fluxo          |
| Uso em gestão        | Ajuda a enxergar gargalos, prioridades, capacidade do time e previsibilidade |
| Diferença para Scrum | Scrum trabalha com Sprints; Kanban trabalha com fluxo contínuo               |
| Principal objetivo   | Fazer o trabalho fluir melhor, com menos acúmulo e mais previsibilidade      |

---

## Conceitos principais

| Conceito          | Explicação curta                                                                          |
| ----------------- | ----------------------------------------------------------------------------------------- |
| Fluxo de trabalho | Caminho que uma demanda percorre do início até a entrega                                  |
| Quadro Kanban     | Visualização das etapas do trabalho, como “A fazer”, “Em andamento” e “Concluído”         |
| WIP               | Work in Progress; quantidade de itens iniciados e ainda não finalizados                   |
| Limite de WIP     | Restrição para evitar excesso de trabalho em andamento                                    |
| Gargalo           | Ponto do fluxo onde o trabalho acumula e a entrega fica lenta                             |
| Pull system       | O time puxa novo trabalho quando existe capacidade, em vez de empurrar tarefas sem limite |
| Lead Time         | Tempo total desde a solicitação até a entrega                                             |
| Cycle Time        | Tempo desde o início real do trabalho até sua conclusão                                   |
| Throughput        | Quantidade de itens concluídos em determinado período                                     |

---

## Kanban na gestão de projetos

| Situação               | Como Kanban ajuda                                  |
| ---------------------- | -------------------------------------------------- |
| Muitas tarefas abertas | Limita WIP e força foco                            |
| Falta de visibilidade  | Mostra onde cada demanda está                      |
| Atrasos frequentes     | Ajuda a identificar gargalos                       |
| Prioridades confusas   | Torna o fluxo e as filas mais explícitos           |
| Time sobrecarregado    | Mostra excesso de demanda versus capacidade        |
| Baixa previsibilidade  | Usa métricas de fluxo para estimar melhor entregas |

---

## Boas práticas

| Prática                     | Benefício                                     |
| --------------------------- | --------------------------------------------- |
| Visualizar o fluxo          | Aumenta transparência                         |
| Controlar WIP               | Reduz multitarefa e sobrecarga                |
| Gerenciar itens ativos      | Evita que demandas envelheçam no quadro       |
| Tornar políticas explícitas | Define critérios claros para mover itens      |
| Medir fluxo                 | Melhora decisões com dados                    |
| Melhorar continuamente      | Ajusta o processo conforme problemas aparecem |

O **Kanban Guide** define Kanban como uma estratégia para otimizar o fluxo de valor por meio de três práticas: definir e visualizar o fluxo, gerenciar itens ativamente e melhorar o fluxo. ([Kanban Guides][2])

---

## O que memorizar

| Pergunta                       | Resposta curta                                        |
| ------------------------------ | ----------------------------------------------------- |
| Para que serve Kanban?         | Para gerenciar e melhorar o fluxo de trabalho         |
| O que é WIP?                   | Trabalho iniciado e ainda não finalizado              |
| Por que limitar WIP?           | Para reduzir acúmulo, multitarefa e gargalos          |
| Kanban exige Sprint?           | Não; Kanban trabalha com fluxo contínuo               |
| Principal vantagem para gestão | Dar visibilidade, previsibilidade e controle do fluxo |

# English Version — Section 5: Kanban

## Short Summary

| Topic                 | Main Idea                                                                 |
| --------------------- | ------------------------------------------------------------------------- |
| What Kanban is        | A visual method to manage workflow and improve value delivery             |
| Focus                 | Visualize work, limit work in progress, and improve flow                  |
| Management use        | Helps identify bottlenecks, priorities, team capacity, and predictability |
| Difference from Scrum | Scrum works with Sprints; Kanban works with continuous flow               |
| Main goal             | Make work flow better, with less accumulation and more predictability     |

---

## Key Concepts

| Concept      | Short Explanation                                                                  |
| ------------ | ---------------------------------------------------------------------------------- |
| Workflow     | The path a work item follows from start to delivery                                |
| Kanban board | A visual representation of work stages, such as “To Do”, “In Progress”, and “Done” |
| WIP          | Work in Progress; items started but not finished                                   |
| WIP limit    | A restriction used to avoid too much work in progress                              |
| Bottleneck   | A point where work accumulates and delivery slows down                             |
| Pull system  | The team pulls new work when there is capacity                                     |
| Lead Time    | Total time from request to delivery                                                |
| Cycle Time   | Time from actual work start to completion                                          |
| Throughput   | Number of items completed in a given period                                        |

---

## Kanban in Project Management

| Situation           | How Kanban Helps                         |
| ------------------- | ---------------------------------------- |
| Too many open tasks | Limits WIP and improves focus            |
| Lack of visibility  | Shows where each work item is            |
| Frequent delays     | Helps identify bottlenecks               |
| Unclear priorities  | Makes queues and workflow explicit       |
| Overloaded team     | Shows demand versus capacity             |
| Low predictability  | Uses flow metrics to improve forecasting |

---

## Good Practices

| Practice                   | Benefit                                      |
| -------------------------- | -------------------------------------------- |
| Visualize the workflow     | Increases transparency                       |
| Control WIP                | Reduces multitasking and overload            |
| Actively manage work items | Prevents items from aging unnecessarily      |
| Make policies explicit     | Clarifies when items can move between stages |
| Measure flow               | Supports data-informed decisions             |
| Improve continuously       | Adjusts the process as problems appear       |

The **Kanban Guide** describes Kanban as a strategy to optimize value flow through three practices: defining and visualizing workflow, actively managing items, and improving workflow. ([Kanban Guides][2])

---

## What to Memorize

| Question                     | Short Answer                                          |
| ---------------------------- | ----------------------------------------------------- |
| What is Kanban used for?     | To manage and improve workflow                        |
| What is WIP?                 | Work started but not yet finished                     |
| Why limit WIP?               | To reduce accumulation, multitasking, and bottlenecks |
| Does Kanban require Sprints? | No; Kanban works with continuous flow                 |
| Main management benefit      | Visibility, predictability, and flow control          |
